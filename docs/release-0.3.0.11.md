# Archai 0.3.0.11

Unreal now runs as a real engine library inside Archai's Windows desktop process. Live geometry, textures, view settings and scene updates use an in-memory native bridge. The modeling document and Archai interface remain in Archai. Opening a rendered view does not launch Unreal Editor or a separate rendering executable. The bundled library, native host and cooked content supply the viewport; ordinary viewing does not require an Unreal installation.

Closing a rendered view retains its scene for five minutes. Prepared scene snapshots and a content-addressed disk cache also avoid repeating geometry preparation and upload after reopening or restarting. Very large uploads are divided into bounded batches and mesh sections. Missing or evicted cache data is reconstructed from the project. Cache data is disposable and never replaces the original project.

Native input fixes activate the hosted game viewport, synchronize Unreal's hit-test bounds with its visible surface, process pending Windows input and configure desktop mouse capture after player possession. Picking and placement use the hosted surface's current pixel coordinates on scaled displays. Default 3D creation also bypasses the selection gizmo and continues past vertical walls when looking for a placement surface.

The View tab includes automatic or fixed exposure with the existing exposure slider. Unreal histogram ranges and initial adaptation are calibrated to avoid the initial overexposed frame. Area lights retain independent width and height; spotlights retain inner and outer cone angles. Lighting remains editable with ordinary Archai light elements.

Interactive folders preserve the selected renderer, style, selected elements and lighting choice. Native Unreal desktop/PC OpenXR folders include the player; saved Lightmass folders retain their cooked illumination. Optimized WebXR links run in desktop and headset browsers with approximate lighting. They do not execute Unreal Lumen inside the browser. A native Unreal bake is optional for real-time folders and optimized WebXR links. Authoring a Lightmass bake currently uses the configured local Unreal build worker; visitors do not need the editor.

Verification covers the actual DLL loaded in Archai's process, live updates, rendered images, exposure, scene retention, new sessions and shutdown; actual pointer picking, orbit and direct element placement from the installer payload; and a synthetic 1,046,528-triangle model with all triangles preserved. The installer-payload check measured approximately 13.8 seconds for first loading, 0.25 seconds for retained reopening including image capture, and 7.6 seconds for restoring from disk with zero binary uploads. Initial preparation still had a 740 ms UI heartbeat gap. These measurements are specific to this computer and fixture.

The release passed 25 targeted unit tests and five browser tests. Packaged checks verified the full viewport behind panels, five styles, three light types, a 1280×720 image export, selected-element interactive export, portable WebXR launch, standalone Unreal folder rendering and cooked Lightmass player/folder rendering. Native viewing passed with an unavailable editor path. Extracted installer DLL and host hashes match the tested runtime and source build. Verification used isolated profiles and synthetic projects; existing projects were not opened or modified.

Physical headset operation and production uploads are not covered by the automated checks. Large scene support remains subject to available memory and GPU capacity; the synthetic rendering benchmark is not proof of arbitrary building size or large-scene Lightmass performance.
